Diferenças encontradas no caminho e corrigidas (todas reais):
  1. Transformei .cost__progression no próprio <ul> — os <li> viraram itens
     flex e enfileiraram. Voltou a ser <div><ul>...</ul></div>.
  2. Unifiquei .section-title-kw--* com .hero__subtitle-kw--* num .kw--N, mas
     os do título NÃO tinham font-weight (o peso já é o do título). Corrigido
     com `.section-title .kw--N { font-weight: inherit }`.
  3. Reformatei texto dentro de <h1>/<p>/<button>: a quebra de linha no HTML
     vira espaço e desloca o texto. Todo texto voltou a ficar em linha única.
  4. Usei `transform: none` no estado revelado, onde o original tem
     `translateY(0)` — isso troca o antialiasing do texto (camada de
     composição). Voltou para translateY(0).
  5. Removi `position: relative` do bloco da calculadora; sem ele o Chromium
     muda o antialiasing da seção inteira. Restaurado e comentado.
  6. Os dois elementos vazios removidos (#future-content e .calc__number)
     ocupavam um `gap` cada. Compensado de forma explícita:
     .cost__highlight { margin-bottom: var(--space-5) } e, no mobile,
     .calc { padding-top: var(--space-2) }.
